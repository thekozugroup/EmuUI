# Integrated source cores and Play assets

This supersedes the candidate-only state in SOURCE_CANDIDATES_AND_GATE_QA.md. Three exact source-built arm64/API23 cores now replace WonderSwan, PPSSPP and Citra in both Play feature modules and bundled QA. The upstream core submodule remains unmodified. All other native files, including both DS cores, must match the previous validated baseline. Citra remains subject to the existing 3DS UI limitation; no system was additionally removed or enabled.

## Reproduce the input set

Use `python3 qa/stage_source_release_inputs.py /path/to/deliverables` to stage Source-built-release-native-inputs.zip, verifying hashes without network access. For rebuilding rather than staging, use wswan/ppsspp/citra-api23-source-candidate.tar.gz and REBUILD-CANDIDATES.md. Citra is additionally stripped with the installed NDK `llvm-strip --strip-unneeded` (296,758,200 to 30,232,984 bytes), exactly matching Android library release stripping; its unstripped source-candidate archive is preserved. This changes debug symbols, not emulation code. Place the final binaries in `.release-native/arm64-v8a/`, named `libmednafen_wswan_libretro_android.so`, `libppsspp_libretro_android.so`, `libcitra_libretro_android.so`. `qa/source-core-binaries.json` locks the exact successful builds. Gradle verifies hashes and stages a replacement native directory for each affected module. Missing/wrong inputs fail the build; no fallback to untraced binaries. Sources/configuration/link maps and all fetched license files accompany the source archives. These local inputs are intentionally not committed as compiled binaries.

The cleaned `PSP-play-bundled-assets.zip` goes at `.release-native/assets/core-assets/ppsspp.zip`, locked by `qa/source-core-assets.json`. The Play updater reads this from AssetManager with no network fallback. The free flavor retains its previous network path. Existing asset version/settings and saves are preserved; existing installed assets are not forcibly replaced. New installs extract the same 137 content files. Only two Git metadata pointer files are excluded. This adds about 9 MB compressed assets to the Play bundle.

Every runtime asset has an exact Git-blob match recorded in qa/psp-assets-provenance.json: 124 files under assets/ and two images under source_assets/image/ in PPSSPP c6352a262d272468e867138f3d3310234302210b; eleven debugger files in unknownbrackets/ppsspp-debugger 9776332f720c854ef26f325a0cf9e32c02115a9c. The debugger source maps embed all 656 original JS/CSS source entries. The deployment commit explicitly identifies debugger original source e47358f0b7c59737bca23a2efab114d686aff5ca; its package declares GPL-3.0-or-later and the source archive includes its build scripts and lockfile. The matching source snapshots are included in PSP-runtime-assets-corresponding-sources.tar.gz. The earlier 52-file/two-image provenance gaps are resolved. Font licenses remain Ume / Adobe SIL OFL as previously documented. These assets contain no game ROM or BIOS.

## Validation scope

Three replacements pass ELF LOAD and RELRO 16 KB alignment, actual 16 KB dlopen/API metadata and two retro_init/retro_deinit cycles each with no content. PPSSPP's minimal standalone probe reports missing assets/JVM attachment, as expected outside the app; its clean exit does not certify rendering. There are no available lawful PSP, WonderSwan or 3DS gameplay fixtures in this workspace, so their gameplay and old save/state compatibility are UNRUN. No existing save was migrated, deleted or used as a fixture. User-reported DS save success remains preserved.

The full minified ExternalGameLauncherActivity route reaches billing without reflection; the earlier ten-second timeout was insufficient on this emulator. Production remains fail-closed while public Play product configuration is absent. Real Play purchases/delivery are not tested by local debug signing.
